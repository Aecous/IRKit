# 调查报告写作模板

由主 Agent 撰写，完整复核模式也可由已有综合 Agent 提交。不新增写作 Agent。

写作依据是当前有效的事件事实、关系、排查结果和原始证据。上下文负责组织思路；有冲突时回到证据。仅整理已有结果时，不重跑调查，也不把旧任务改判为完成。

## 1. 事件概述

先说明涉及哪些系统、可见时间范围和日志来源，再用两至四段概括主要攻击路线与已证实影响。首次可见活动不等于真实攻击起点。不要复述内部项目目录、任务状态或卡片数量。

## 2. 攻击链路还原

按能够解释的独立链路分小节。每条链先用一句话概括，再按步骤连续叙述：

> 时间与时区 → 谁对哪个系统做了什么 → 记录的结果 → 如何关联下一步。

区分环境与主机。关联依据可以是进程父子关系、会话、任务标识或其他直接证据；相同 IP、账号或相近时间仅能支持相应强度的线索关联。连接不足时在“关联依据与边界”说明，不添加自动连接箭头。正文无需 Mermaid 即可读懂。

## 3. 后渗透操作与影响

分别讲清凭据/账号操作、执行与持久化、横向移动、业务数据访问与收集、外传尝试及清理痕迹。按实际发现取舍。

尝试执行、进程启动、操作完成和造成影响是不同结论。日志记录了打包命令不代表归档完成；传输程序启动不代表远端收到文件；应用响应成功也不自动证明越权。明确已证实影响及未知部分。

## 4. 攻击时间线与来源

时间线只列关键转折，最多 40 行。每行注明时间/时区、来源、目标、简短行为和结果。来源表区分直连对端、跳板、外联目标与可归因来源，不能把所有地址都列为攻击 IP。

## 5. 调查局限与处置建议

只写影响结论的实际限制，如未提供代理访问日志、缺少网络流量字节证据或授权基线。建议与已经发现的行为对应。卡片过期、待复核、任务未完成等内部流程信息保留在工作台，不输出给报告读者。

## 提交结构

`render_report.report_content`：

- `scope_note`：背景、系统和时间范围。
- `conclusions`、`impacts`、`recommendations`：Finding 列表。
- `attack_chains`：`{title, scope, summary, steps, connections}` 列表；后三者分别为 Finding、Finding 列表、Finding 列表。
- `post_exploitation`：Finding 列表。
- `timeline`：`{time, source, target, activity: Finding}` 列表。
- `sources`：`{address, role, activity: Finding}` 列表。

Finding 为 `{text, certainty, evidence}`，certainty 为 `confirmed`、`possible` 或 `unknown`。证据为 `{object_id, revision, claim_key?}`；结构化事实必须引用具体 claim_key。已确认/可能的结论都需要证据，明确无法确认的结论可无证据。所有区域使用同一引用校验。

正文自动生成简短 E 编号。引用对应的原件路径、SHA-256、原始行或 EVTX 文件内记录序号、查询和统计口径进入独立证据附录。正文与附录各有 Markdown、HTML 两种格式。报告文件生成、运行交付与人工审阅状态分别保留。

## 从 Web 下发报告写作

在「下发调查任务」选择「基于当前结果生成报告」，再选择所属项目和具体调查。默认预算为 1,000 美元。系统使用新的主 Agent 会话读取已有结果；只提供读取现有对象、证据回查和报告生成工具，不提供入库、查询扩展、修改卡片、创建任务或子 Agent 工具。

此任务新增报告及会话记录，保留原有事实和调查状态。只有本轮新增、五章结构完整、引用仍有效且正文/附录均已落盘，模型会话也正常结束，才显示结果报告完成。旧报告不能满足本轮交付。内部复核/调查未决项仍留在工作台，报告正文陈述真实证据局限。

报告写作模式的 `case_context` 仅返回案件标识、分页背景、对象数量与卡片状态计数；不附带源文件、分区来源清单或任务摘要。通过 `next_background_offset` 读取剩余背景，通过 `list_objects` 的 `next_offset` 读取卡片、关系和补证。该模式不暴露 `closure_readiness` 工具；调查交付检查仍由正常调查流程使用。
